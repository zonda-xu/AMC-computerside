# 电脑连接助手

Windows、macOS、Linux 分别提供独立包。包内只有浏览器向导、电脑网关、协议适配器、DSH 插件和运行所需的 JavaScript 依赖，不包含 HarmonyOS 工程、人物素材、手机构建缓存或个人凭据。

## 第一次启动

1. 完整解压对应系统的 ZIP，不要从压缩包内直接运行。
2. 安装 Node.js **24.13+，且主版本为 24**，以及 OpenSSL。Node.js 自带 SQLite；无需安装 Python，也无需执行 npm install。工具包没有捆绑 Node.js、OpenSSL 或 AI 程序。
3. Windows 双击 `Start-Windows.cmd`；macOS 打开 `Start-macOS.command`；Linux 运行 `Start-Linux.sh`。macOS / Linux 若没有执行权限，在包所在目录执行 `chmod +x Start-macOS.command` 或 `chmod +x Start-Linux.sh`，再运行 `./` 加文件名。Linux 文件管理器通常需要选择“在终端运行”。
4. 浏览器打开仅绑定 `127.0.0.1` 的本机向导。如果没有自动打开，复制启动窗口显示的地址。同一用户重复启动会打开已有向导。
5. 保留启动窗口。关闭浏览器不会停止网关；退出启动进程将停止由它管理的网关。当前未安装开机服务，也不会自动修改防火墙或提权。

Windows 可通过 Git for Windows 提供 OpenSSL，助手支持其默认安装路径；macOS 可通过 Homebrew 安装 OpenSSL；Linux 使用发行版的 OpenSSL 软件包。AI CLI 安装后需要在同一电脑用户下先完成官方登录。Windows 支持原生 exe 及常见 npm Node.js cmd 启动器，无法识别的批处理应改为原生程序路径。

## 五步完成配对

1. **准备环境**：查看 Node.js、OpenSSL 和本机私有 IPv4 地址。缺少依赖时按当前系统的说明安装，再检测。
2. **选择连接方式**：推荐首次使用同一 Wi-Fi。填写电脑名称、选择手机能够访问的网卡。远程模式另填受控域名。
3. **接入 AI 终端**：选择已有项目目录，勾选已安装的 Codex、Claude Code、OpenCode 或 DeepSeek Harness，检测完整版本。保存时会重新执行版本检测，不会把手工输入的版本当作检测结果。
4. **手机扫码配对**：启动网关并生成二维码。手机进入 AI Maid Café → 添加主机 → 扫描配对二维码；也可将下载的配对 JSON 内容粘贴到手机对应入口。二维码有效期 120 秒，仅能兑换一次，重新生成会使此前未兑换的二维码失效。
5. **开始使用**：在手机“工作区”登记向导显示的项目目录，再新建会话并选择 AI 程序。先发起一个读取目录结构的小任务，验证真实回复与权限确认。桌面会显示已配对设备，可撤销其访问权限。

“版本已检测”只代表可执行文件可运行。程序登录、账号余额、模型可用性和原生协议兼容性需要在手机首次真实任务中验证。此工具不接管任意已经打开的终端窗口；手机通过现有四种协议适配器创建与管理会话。

## 两种网络

### 同一 Wi-Fi / 局域网

电脑网关绑定选定的私有 IPv4 地址和 TCP 8899，并生成包含该 IP 的 TLS 证书。手机需要与电脑互通；访客网络、AP 隔离或防火墙可能阻断连接。仅在可信网络允许网关的入站访问，无需关闭整个防火墙。

电脑 IP 变化后，停止网关、更新地址、保存并重新启动；手机移除旧主机后重新扫码。建议在路由器固定电脑的 DHCP 租约。项目目录不是原生 AI 的系统沙箱，原生程序仍使用其自身权限。

### EasyTier 远程中转

沿用原工程的独立 `agent-console-mesh` 网络：

| 系统 | 本机虚拟 IP | 服务器公网 TCP 入口 |
|---|---|---|
| Windows | 10.89.90.2 | 18543 |
| macOS | 10.89.90.3 | 18541 |
| Linux | 10.89.90.4 | 18542 |

1. 在电脑与 VPS 安装与你已验证部署一致的 EasyTier，工程配置基线为 2.6.4。
2. 在向导中填写已解析到 VPS 的域名。首次部署可生成新的网络密钥；追加电脑必须使用同一 App 网络密钥。不要误用个人网络的密钥。
3. 下载 `host.toml` 和 `relay.toml`。主机文件仅配置当前系统的虚拟 IP；中转文件包含三条独立 TCP 映射。两份文件包含网络密钥，应保存在私有目录，不上传公开仓库。
4. Windows 可在 EasyTier GUI 导入 `host.toml`，或在管理员终端执行 `easytier-core.exe -c host.toml`。macOS / Linux 按安装位置执行 `sudo easytier-core -c host.toml`。提权只用于创建网络接口；助手自身不需要管理员权限。
5. 在 VPS 的独立目录运行 `easytier-core -c relay.toml`，开放组网 TCP 12080 和需要的 18541 / 18542 / 18543 入口。已有中转服务时先比较配置，不要直接覆盖或影响现有网络。
6. 返回向导重新检测网卡。指定虚拟 IP 出现后才可保存。服务器只透传 TCP，由电脑网关终止 TLS。
7. 启动网关，运行“检测连接入口”，检查公网入口返回的证书和主机身份，再用手机移动网络扫码确认。

生成配置不等于已安装、已部署或已连通。向导不会替你访问 VPS、修改路由或开启系统服务。当前固定映射适合每种系统各一台电脑；同一种系统多台电脑需要扩展地址和端口规划。

官方配置参考：[EasyTier 配置文件](https://easytier.rs/guide/network/config-file.html)。Node.js 下载：[Node.js 24 安装包](https://nodejs.org/en/download/archive/v24.18.0)。

## 数据和信任

私有数据默认位于当前用户的 `.ai-maid-cafe/desktop/`，包含 `host.config.json`、证书、CA 私钥、DSH 桥接密钥和 SQLite 设备记录。配置中的文件路径是绝对路径；不要把这个目录复制给其他电脑。分发只使用原始 ZIP。

再次启动时沿用已有 hostId 与 CA；保存配置会签发新的服务证书，不重新创建电脑身份。网关运行时不能保存配置。要修改设置，先确认任务已结束，再点击“停止网关”。已登记工作区或会话的数据会保留，修改项目目录不会删除历史记录。

本机管理接口使用每次启动生成的随机凭据，只绑定回环地址，并检查 Host / Origin。不把凭据放入查询参数或远程资源。浏览器关闭后二维码不持久保存在浏览器；主动下载的 PNG / JSON 仍应妥善保管。

DSH 额外需要加载 `plugins/dsh-bridge/index.mjs`，配置 `gatewayUrl: ws://127.0.0.1:8898`、向导显示的 `tokenFile` 路径和实测 `hostVersion`。手机凭据和桥接凭据互不通用。

## 排查

- **助手打不开**：确认 Node.js 为 24.13+ 的 24.x、解压完整且数据目录可写。先打开包内 `START-HERE.html` 查看离线说明。
- **另一个网关正在运行**：先结束原 CLI 网关或另一份电脑助手，然后重试。网关保持每个系统用户单实例约束。
- **网关启动失败**：检查本机 IP 是否存在、8899 和本机 8898 端口是否占用。查看原先的网关是否仍在运行。
- **扫码超时**：检查同一 Wi-Fi、防火墙、访客网络隔离；远程模式检查 EasyTier 与 VPS 转发。
- **证书失败**：检查两端时间、目标 IP / 域名和端口映射，不要关闭 TLS 校验。
- **程序路径无效**：填写可执行程序名或绝对路径，不添加引号或命令行参数。检测失败时检查安装和权限。
- **已配对但 AI 无响应**：先在电脑确认官方 CLI 已登录且能正常对话，再检查适配器版本和 DSH 插件配置。配对成功不等于原生 AI 任务已经验收。

## 在源码工程运行与打包

```text
npm run desktop
npm run package:desktop
```

打包输出在 `dist/desktop/<时间戳>/`，包括三份独立 ZIP、解压后的目录、`manifest.json` 和 `SHA256SUMS.txt`。打包采用明确目录白名单，仅打包运行时依赖，保留第三方依赖的许可证文件。每次使用新目录，不覆盖旧产物。Node.js 和 OpenSSL 是外部依赖，ZIP 本身不是带系统签名的原生安装程序。
