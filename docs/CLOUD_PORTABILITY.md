# 云厂商无关的中转部署契约

本项目不调用云厂商 SDK，也不把某一账号、区域、镜像或公网地址写进控制协议。云服务器只承担 EasyTier peer 与四层 TCP 转发；身份、TLS、配对、工作区授权、事件持久化和四平台原生控制均留在主机。更换云厂商不应要求修改手机或适配器代码。

## 必须满足的基础能力

| 项目 | 要求 |
| --- | --- |
| 运行环境 | 可运行目标架构的 EasyTier；Compose 部署须先准备匹配架构、已核实 digest 的镜像 |
| 公网入口 | 可达的 DNS 名称和 TCP 端口；域名与主机证书 SAN 一致 |
| 转发 | 原样传递 TLS 字节，不能把 HTTPS/WSS 改成未受信任的明文后端 |
| 网络授权 | 同时检查云安全组、云防火墙、宿主防火墙与容器端口映射 |
| 独立网络 | `agent-console-mesh`、`10.89.90.0/24`、peer TCP `12080`，不复用个人网络密钥 |
| 主机入口 | Windows `18543 → 10.89.90.2:8899`、macOS `18541 → 10.89.90.3:8899`、Linux `18542 → 10.89.90.4:8899` |
| 原生服务 | Codex `8897`、DSH 桥 `8898` 及 OpenCode 服务继续只在主机 loopback；不向 VPS 暴露模型凭据 |

云厂商的安全组字段名称、系统镜像和管理界面可以不同，上述数据面契约不变。普通 HTTP 反向代理不等于四层透传；若使用负载均衡，必须明确选择 TCP/TLS 透传而非另建一个不匹配手机信任的 TLS 终止点。不要通过关闭证书校验解决域名或转发配置错误。

## 可重复生成，而非绑定个人配置

1. 使用 `deploy/easytier/profile.example.json` 建立部署副本，更换 `relayPublicHost` 和实际主机标识，保留计划中的隔离网络与三主机映射。
2. 在受保护环境变量 `ET_NETWORK_SECRET` 中提供新的至少 256 位随机 base64url 网络密钥，不写入命令历史、日志或公开配置。
3. 使用 `node deploy/easytier/render.mjs <profile.json> <output-directory>` 生成 TOML。脚本只生成文件，不启动 Docker、不改路由，并拒绝覆盖已有 `relay.toml`。
4. 在实际部署目录使用仓库 Compose 模板，设置经过核实的 `ET_IMAGE` digest，按厂商各自工具开放所需 TCP 入口。不要将主机 CA 私钥、配对数据库或模型凭据复制到云服务器。
5. 更换云服务器时保留主机身份和证书体系；若更换公网域名，只在原 CA 下重新签发匹配 SAN 的主机叶证书并更新入口配置，不伪造为另一主机，也不自动重发未确认命令。

## 故障边界

- 公网 TCP 不通：检查安全组、防火墙、实例公网路由和端口映射。
- EasyTier 不通：检查独立网络身份、密钥、peer 连接及主机 overlay 地址。
- TLS 失败：检查 SAN、CA、有效期及字节透传，不改为“不校验证书”。
- 手机重连：从网关持久 seq 与快照恢复；不创建第二个原生写入进程。
- 某个模型平台不可用：显示该运行时协议与认证能力，不能把云端在线灯当成引擎可运行证据。

`tests/contracts/relay-portability.test.ts` 检查不同云域名不会改变标准转发语义、原生文件路径下 CLI 能实际生成配置、重复执行不覆盖密钥文件。这些是可移植性契约测试，不冒充各家云服务器的公网实测；真实公网质量与厂商网络限制另行验收。
