# 电脑连接助手验证记录

日期：2026-11-12。开发环境：Windows，Node.js 24.18.0，Git for Windows OpenSSL。

## 自动验证

电脑端保留 40 项协议、适配器与网关回归测试，新增 5 项电脑助手测试。手机人物素材检查单独保留在原工程的 `tests/assets/`，不要求独立电脑仓库携带手机素材。新增测试覆盖：

- 私有网卡 / 域名 / 项目目录校验，非法配置不会覆盖现有配置。
- Windows npm cmd 启动器解析为 Node.js 入口，不经过命令 Shell。
- 本机管理接口拒绝未认证、跨站 Origin 和伪造 Host，敏感文件不作为静态资源公开。
- 配置重复保存保留 hostId 与 CA，服务证书包含实际连接 IP。
- 真实子进程网关启动、证书验证、二维码内容生成、TLS 兑换、旧码失效和单次兑换。
- 在线 WSS 设备撤销后立即关闭连接，旧 token 无法再访问接口。
- 停止和重启网关，运行期间拒绝覆盖配置。
- 缩小项目授权目录后，不延续旧工作区的文件 / 执行授权，历史记录保留。

测试中的版本检测使用 Node.js 作为固定输出样本，不启动真实 AI 任务。发布前运行 TypeScript 检查、源码检查和完整测试集。

跨平台测试夹具先解析临时目录真实路径，兼容 macOS 的 `/var` 别名与 Windows 云端 runner 的短路径；生产网关同样先规范化项目授权目录。

## 界面验证

在本机浏览器走通环境检测、网络选择、程序版本检测、保存配置、启动网关、生成二维码和 TLS 入口检测。检查桌面及 390px 窄屏布局，窄屏无横向溢出，保留停止入口。二维码可另开大图，过期后隐藏。

机械界面检查的缺失图片 src 提示对应隐藏的动态二维码容器：二维码生成后才设置真实 data URL，未生成、失效或关闭状态下不会显示破损图片。

## 分发与未覆盖项

分发使用明确目录白名单，检查无 HarmonyOS、素材、私钥、设备数据库或个人配置。运行依赖按生产依赖闭包复制；每次生成三个 ZIP 与 SHA-256 清单，保留脚本 Unix 执行位和第三方依赖许可证。

Windows 已完成本机运行验证。macOS / Linux 通过同一源码构建各自启动包，发布流水线在三个系统运行自动测试，但图形桌面、系统安全提示、不同 CPU 架构与手机实际扫码需要在相应机器上确认。
